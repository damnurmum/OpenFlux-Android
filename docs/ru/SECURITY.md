# Политика безопасности

## Сообщить об уязвимости

Не открывайте публичный issue для уязвимости, которая раскрывает секреты,
позволяет расшифровать трафик или даёт удалённый доступ к системе.
Используйте приватную функцию GitHub **Security → Report a vulnerability**
в этом репозитории. Если приватные отчёты об уязвимостях отключены, свяжитесь
с владельцем репозитория напрямую и приложите минимальный воспроизводимый
пример.

Не включайте в отчёт реальные ссылки на документы, ключи шифрования, адреса
серверов, логи с учётными данными или приватные ключи подписи APK.

## Модель безопасности и ограничения

- Трафик, передаваемый через транспорт-документ, шифруется и
  аутентифицируется AES-256-GCM. Ключи выводятся из общего секрета через
  scrypt.
- Провайдер документа по-прежнему видит метаданные соединения, тайминги,
  размеры пакетов и зашифрованные данные. Сквозное шифрование не скрывает
  метаданные.
- Любой с правом редактирования документа может нарушить доступность
  соединения, даже не имея возможности расшифровать или подделать трафик.
- Android защищает сохранённую ссылку и общий секрет через Android Keystore.
  Они удаляются при очистке данных приложения или его удалении.
- Текущий Android-клиент - экспериментальная реализация IPv4 TCP/UDP. Его нельзя
  считать проверенной аудитом заменой WireGuard или другого зрелого VPN.

Используйте уникальный случайно сгенерированный секрет, защищайте файлы на
VDS правами `0600`, не коммитьте секреты и меняйте и ссылку на документ, и
ключ после утечки.
