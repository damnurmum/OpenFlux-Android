# Гайд для новичков: разворачиваем OpenFlux на своём VPS

[English](../en/GUIDE.md) · **Русский**

Этот гайд - пошаговая инструкция «от и до»: как арендовать сервер, поднять
на нём exit-node OpenFlux и подключиться к нему с Android-телефона. Он
рассчитан на то, что вы никогда раньше этого не делали.

Если что-то в этом гайде не совпадает с основным [README.ru.md](../../README.ru.md) -
доверяйте README, там более полное и актуальное описание. Здесь - упрощённый
путь для первого запуска.

> Программа экспериментальная и не заменяет полноценный VPN вроде WireGuard.
> Используйте её только на своих серверах и сетях. Подробнее - в
> [SECURITY.md](SECURITY.md) и в разделе «Важные ограничения» README.

## Как это вообще работает

OpenFlux не подключается к вашему серверу напрямую - вместо этого клиент
(Android-приложение) и сервер (exit-node на VPS) обмениваются трафиком через
**общий документ Yandex Docs**. Документ здесь - просто точка встречи, весь
трафик внутри него зашифрован ключом, который знаете только вы.

```
Android-приложение <-> зашифрованный трафик через документ Yandex Docs <-> ваш VPS (exit-node) <-> интернет
```

Значит, вам нужны три вещи:
1. **Документ Yandex Docs**, на который будут смотреть и телефон, и сервер.
2. **Секрет шифрования** - одна и та же строка на телефоне и на сервере.
3. **VPS с root-доступом**, на котором будет крутиться exit-node.

## Что понадобится

- VPS (любой провайдер) с root-доступом, желательно на Ubuntu/Debian;
- SSH-клиент, чтобы подключиться к серверу (в Windows подойдёт встроенный
  `ssh` в PowerShell/Терминале, в macOS/Linux - обычный Терминал);
- аккаунт Яндекса для создания документа;
- Android-телефон версии 8.0 и новее.

Собирать что-либо из исходного кода не нужно - используем готовые файлы из
[GitHub Releases](https://github.com/damnurmum/OpenFlux-Android/releases/latest).

## Шаг 1. Подготовьте документ Yandex Docs

1. Зайдите на [docs.yandex.ru](https://docs.yandex.ru) под своим аккаунтом
   и создайте новый текстовый документ.
2. OpenFlux работает только со **старым (классическим) редактором**
   документа - в новом редакторе транспорт не работает и приложение может
   упасть с ошибкой. Если документ открылся в новом редакторе, поищите в
   интерфейсе документа переключатель на старую/классическую версию
   редактора (обычно это баннер или пункт в настройках/справке самого
   документа - Яндекс периодически меняет расположение этой опции, так что
   могут понадобиться пара кликов методом подбора). Если переключателя нет -
   попробуйте создать документ заново либо через Яндекс.Диск.
3. Откройте доступ на **редактирование** по ссылке (не только на просмотр) -
   и клиенту, и серверу нужно право писать в документ, чтобы обмениваться
   данными.
4. Скопируйте ссылку на документ - она понадобится и на телефоне, и на
   сервере.

> Эта ссылка равносильна паролю на подключение к вашему туннелю - не публикуйте
> её и не отправляйте посторонним. Любой человек с правом редактирования
> документа может оборвать соединение (не расшифровав трафик, но и не
> заботясь об этом ему для этого не нужно).

## Шаг 2. Придумайте секрет шифрования (опционально, но рекомендуется)

Шифрование транспорта необязательно - без него OpenFlux работает так же, как
обычная нода апстрима. Но если у вас свой exit-node, рекомендуем включить
его: нужна случайная строка **не короче 16 символов**, одинаковая на телефоне
и на сервере. Проще всего сгенерировать её прямо в Android-приложении на
шаге 4 кнопкой «Сгенерировать безопасный ключ» и потом скопировать на
сервер. Либо сгенерируйте заранее в терминале на своём компьютере:

```bash
openssl rand -base64 32
```

Сохраните вывод команды - это и есть ваш секрет. Не используйте обычный
пароль, придумайте случайное значение специально для этого.

## Шаг 3. Установите exit-node на VPS

Дальше все команды выполняются на сервере - подключитесь к нему по SSH:

```bash
ssh root@ваш_ip_адрес
```

### 3.1. Скачайте готовый бинарник

Узнайте архитектуру процессора сервера:

```bash
uname -m
```

- `x86_64` → берите `OpenFlux-linux-amd64` (самый частый случай);
- `aarch64` или `arm64` → берите `OpenFlux-linux-arm64` (ARM-серверы, часто
  встречаются у облачных провайдеров с ARM-инстансами).

Скачайте и сделайте исполняемым (пример для amd64 - замените имя файла на
`OpenFlux-linux-arm64`, если у вас ARM):

```bash
mkdir -p /root/openflux && cd /root/openflux
curl -LO https://github.com/damnurmum/OpenFlux-Android/releases/latest/download/OpenFlux-linux-amd64
mv OpenFlux-linux-amd64 openflux
chmod +x openflux
```

### 3.2. Положите ссылку на документ (и, если решили шифроваться, секрет) в файлы

```bash
printf '%s\n' 'ССЫЛКА_НА_ВАШ_ДОКУМЕНТ' > /root/openflux/document-url
printf '%s\n' 'ВАШ_СЕКРЕТ_ИЗ_ШАГА_2' > /root/openflux/encryption-key
chmod 600 /root/openflux/document-url /root/openflux/encryption-key
```

Если решили не включать шифрование - файл `encryption-key` не нужен, а флаг
`--encryption-key-file` в шагах 3.4/3.5 нужно убрать из команды запуска.

Подставьте свои значения вместо `ССЫЛКА_НА_ВАШ_ДОКУМЕНТ` и
`ВАШ_СЕКРЕТ_ИЗ_ШАГА_2`.

### 3.3. Разрешите RST-drop в iptables

Технические подробности - почему это нужно - описаны в README. Коротко:
без этого правила ядро сервера будет рвать туннель сразу после установки.

```bash
sudo iptables -C OUTPUT -p tcp --tcp-flags RST RST -j DROP 2>/dev/null || \
  sudo iptables -I OUTPUT 1 -p tcp --tcp-flags RST RST -j DROP
```

Если на этом сервере кроме OpenFlux работают и другие сервисы - посмотрите
более аккуратный вариант с `--local-ip` в основном [README.ru.md](../../README.ru.md#десктопный-cli-выходная-нода-и-клиент),
он не глушит RST для всего хоста.

### 3.4. Проверьте вручную перед автозапуском

```bash
sudo /root/openflux/openflux --role=exit --mode=l3 --transport=yandex \
  --encryption-key-file /root/openflux/encryption-key \
  --url "$(cat /root/openflux/document-url)" --debug
```

Если в логах не видно ошибок и написано что-то вроде «Running as EXIT NODE» -
всё в порядке, остановите процесс сочетанием `Ctrl+C` и переходите дальше.
Если есть ошибки - см. раздел «Частые проблемы» ниже.

### 3.5. Настройте автозапуск через systemd

Создайте файл `/etc/systemd/system/openflux.service`:

```bash
sudo tee /etc/systemd/system/openflux.service > /dev/null <<'EOF'
[Unit]
Description=OpenFlux encrypted exit node (l3, Yandex transport)
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
ExecStartPre=/bin/sh -c '/usr/sbin/iptables -C OUTPUT -p tcp --tcp-flags RST RST -j DROP 2>/dev/null || /usr/sbin/iptables -I OUTPUT 1 -p tcp --tcp-flags RST RST -j DROP'
ExecStart=/bin/sh -c 'exec /root/openflux/openflux --role=exit --mode=l3 --transport=yandex --encryption-key-file /root/openflux/encryption-key --url "$(cat /root/openflux/document-url)"'
ExecStopPost=/bin/sh -c '/usr/sbin/iptables -C OUTPUT -p tcp --tcp-flags RST RST -j DROP 2>/dev/null && /usr/sbin/iptables -D OUTPUT -p tcp --tcp-flags RST RST -j DROP || true'
Restart=on-failure
RestartSec=5
NoNewPrivileges=true
PrivateTmp=true
ProtectHome=read-only
ProtectSystem=strict
ReadOnlyPaths=/root/openflux

[Install]
WantedBy=multi-user.target
EOF
```

Запустите и включите автозапуск при перезагрузке сервера:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now openflux
sudo systemctl status openflux
```

Строка `Active: active (running)` означает, что exit-node работает. Логи в
реальном времени можно смотреть так:

```bash
sudo journalctl -u openflux -f
```

Сервер готов. Дальше - настройка телефона.

## Шаг 4. Установите Android-приложение

1. Откройте [страницу релизов](https://github.com/damnurmum/OpenFlux-Android/releases/latest)
   на телефоне и скачайте нужный APK:
   - большинство современных телефонов (2018 год и новее) → `OpenFlux-android-arm64-v8a-release.apk`;
   - старые 32-битные ARM-устройства → `OpenFlux-android-armeabi-v7a-release.apk`;
   - не уверены - скачивайте `OpenFlux-android-universal-release.apk`, он
     работает на любом устройстве, но чуть больше весит.
2. При установке Android может попросить разрешить установку «из неизвестных
   источников» для приложения, через которое вы скачали APK (браузер,
   Telegram и т.д.) - подтвердите, это стандартное поведение для APK не из
   Google Play.
3. Откройте приложение OpenFlux, перейдите на вкладку **«Настройки»** - это
   вертикальный список, нажмите на пункт, чтобы открыть его, а стрелка слева
   сверху (или системный жест/кнопка «назад») вернёт обратно.
4. Откройте пункт **«Транспорт»** и вставьте:
   - в первое поле - ссылку на документ из Шага 1;
   - во второе поле - секрет шифрования из Шага 2 (тот же самый, что вы
     положили в файл `encryption-key` на сервере). Если ещё не придумали
     секрет - нажмите **«Сгенерировать безопасный ключ»**, скопируйте
     значение и вставьте его в файл `encryption-key` на сервере (Шаг 3.2).
5. Настройки **«Сеть»** (DNS-сервер, MTU) можно не трогать - значения по
   умолчанию подходят для большинства случаев. DNS по умолчанию использует
   `1.1.1.1` через выходную ноду, которой нужна поддержка UDP. Свой DNS должен
   быть числовым IPv4-адресом, доступным с выходной ноды.
6. Вернитесь на вкладку **«Главная»** и нажмите **«Запустить туннель»**.
   Android покажет системный запрос на создание VPN-соединения - подтвердите
   его (это стандартный диалог Android, а не что-то специфичное для
   OpenFlux).
7. Если всё настроено верно, статус сменится на **«Подключено»**. Если
   что-то не так - откройте вкладку **«Логи»**, там будут видны технические
   подробности ошибки.

Готово - трафик телефона идёт через ваш сервер.

Не хотите поднимать полноценный системный туннель? В **Настройках → Режим
работы** переключитесь на **«Прокси (SOCKS5)»** - использует ту же ссылку и
секрет, поднимает локальный SOCKS5-сервер на телефоне без системного запроса
разрешения на туннель, и опционально может быть открыт в локальной сети (с
логином/паролем), чтобы им мог пользоваться другой ваш девайс.

## Тоже неплохо: клиент для компьютера

OpenFlux умеет работать и как SOCKS5-клиент на компьютере (Linux/macOS/
Windows) - подробности в основном [README.ru.md](../../README.ru.md#десктопный-cli-выходная-нода-и-клиент).
Короткая версия - тот же бинарник, что и на сервере, только с флагом
`--role=client` вместо `--role=exit`, и в браузере нужно указать SOCKS5-прокси
`127.0.0.1:1080`.

## Частые проблемы

**Ошибка «document URL» при запуске сервера.**
Проверьте, что файл `document-url` не пустой и не содержит лишних
пробелов/переносов строк. Если используете шифрование, то же самое
проверьте для `encryption-key`, и что секрет там - не короче 16 символов.

**Нужно ли указывать ключ шифрования на сервере, если он уже есть в
приложении?** Да, если решили включить шифрование - сервер и клиент должны
знать один и тот же секрет, иначе соединение не установится. На сервере он
передаётся флагом `--encryption-key-file` (см. Шаг 3.2), в приложении - в
поле «Настройки» → «ТРАНСПОРТ». Ключ необязателен: если оставить поле в
приложении пустым и не передавать `--encryption-key-file` на сервере, туннель
будет работать без шифрования, как обычная нода апстрима.

**Приложение подключается, но сразу рвётся / пинг не идёт.** Обычно это
значит, что не сработало RST-drop правило на сервере (Шаг 3.3) - после
перезагрузки сервера правило iptables сбрасывается, если оно не прописано
через systemd-юнит (наш юнит из Шага 3.5 накатывает правило автоматически
при каждом запуске).

**Приложение падает или не может получить данные документа.** Почти всегда
это означает, что документ открыт в новом редакторе Yandex Docs - вернитесь
к Шагу 1 и переключитесь на старый редактор.

**Обновил(а) APK, и настройки исчезли.** Настройки сохраняются только при
обновлении поверх APK с тем же application ID и тем же сертификатом подписи.
Если раньше стоял debug-сборка из CI, а вы поставили подписанный релиз (или
наоборот) - Android потребует сначала удалить старое приложение, и это
сотрёт сохранённые данные. Ссылку и ключ придётся ввести заново.

**Кто-то другой отредактировал документ, и всё сломалось.** Это ожидаемое
поведение - у документа есть владелец сообщения об этом, и любой с правом
редактирования может нарушить связь. Подробнее - в разделе «Важные
ограничения» [README.ru.md](../../README.ru.md) и в [SECURITY.md](SECURITY.md).
