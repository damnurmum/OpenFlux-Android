# Changelog

Здесь фиксируются все значимые изменения этого форка.

## 0.7.0 - 2026-09-16

### Добавлено

- транспорт `mailru` (канал через "общий курсор" Mail.ru Docs), устроен так
  же, как `yandex`; влит в апстрим и подключён и к CLI, и к Android-приложению.
- ядро exit node пересинхронизировано 1 в 1 с апстримовским `flx-kernel`:
  новые `--role=client|exit|bench-send|bench-sink`, `--inbound=tun|socks5`,
  `--mode=l3|l4`, `--codec=batched|legacy` и единый флаг `--url` (заменяют
  `--exit-node`/`--client`/`--tun`/`--socks5-mode`/`--mode raw|proxy`/
  `--url-file`, которые ещё один релиз принимаются как устаревшие алиасы).
  У `--url-file` нет прямой замены - читайте файл сами через подстановку
  команды в шелле, например `--url "$(cat document-url)"`.
- Android-приложение: добавлены транспорты Cups.online и MAX (oneme/WebRTC),
  выбор кодека (batched/legacy) и поля token/UID для MAX в Настройках - раньше
  были доступны только в CLI. Добавлен недостающий цвет для тега лога
  `[M-DOCS]` (mailru).
- новые кроссплатформенные релизные сборки (darwin/linux/windows,
  amd64/arm64, плюс linux/arm и windows/386) через CI - как в списке ассетов
  релиза апстрима.

### Исправлено

- Android: изменение настройки в разделах "Сеть" или "Режим работы" с
  последующим нажатием "назад" без явного сохранения больше не применяет
  изменение - эти страницы теперь используют тот же паттерн черновик/
  применение, что и редактор профиля.
- Android: мобильный мост (`mobile.Start`/`mobile.StartProxy`) выводил
  контекст KDF для шифрования иначе, чем десктопный CLI, когда ссылка на
  документ не задана (транспорт `oneme`) - это могло незаметно сломать
  расшифровку между Android-клиентом и exit node на CLI для этого
  транспорта. Теперь оба используют одинаковый запасной вариант - имя
  транспорта.
- десктопный клиент: `SocketWatcher` устанавливал прямые/обходные маршруты
  для IP управляющего канала транспорта, но никогда не удалял их при
  остановке - после отключения могли оставаться устаревшие маршруты (также
  не было очистки по `SIGHUP`, например при закрытии окна терминала).
- CI: сборки Android падали, потому что `sdkmanager` не было в `PATH` на
  раннере `ubuntu-latest`; вместо починки удалён избыточный и и так уже
  сломанный шаг `android-actions/setup-android`.

### Изменено

- все упоминания "bypass" (в коде, логах, документации) переименованы в
  "direct" - это VPN-клиент, а не инструмент обхода.
- ребрендинг: акцентный цвет изменён на `#EA1A1A`, новая иконка/лого
  приложения.
- `main.go`, `tun_darwin.go`, `tun_watch.go`, `tun_learn.go`, `tun_other.go`,
  `signals_unix.go`, `signals_windows.go` перенесены в пакет `tunclient/`;
  `bench.go` перенесён в пакет `bench/`. Поведение не изменилось.

## 0.6.0 - 2026-09-13

### Добавлено

- **профили подключения**: сохранение нескольких именованных конфигураций
  подключения (тип транспорта, ссылка на документ, ключ шифрования, иконка)
  и переключение между ними - новая вкладка "Профили" (вторая в нижней
  навигации), выпадающий селектор с иконками над кнопкой подключения на
  главном экране, и экран добавления/редактирования с выбором иконки и
  транспорта Yandex Docs / Yandex Docs (Volga). Существующие установки
  автоматически переносят единственную сохранённую ссылку/ключ в первый
  профиль. `mobile.Start`/`mobile.StartProxy` теперь принимают параметр
  `transportType`, чтобы мост Android мог реально выбирать `vyandex`, а не
  только `yandex`.
- **плитка быстрых настроек**: переключает режим подключения, выбранный в
  приложении для активного профиля, без его открытия. Вместо молчаливого
  отказа открывает приложение, если ещё не выдано разрешение на VPN или не
  настроен ни один профиль.
- **цветные логи с таймштампом**: у каждой строки появился префикс
  `[HH:mm:ss.SSS]`; известные теги окрашены (`[ERROR]`/`[PANIC]` красный,
  `[SUCCESS]` зелёный, `[YDOCS]` жёлтый, `[ANDROID]`/`[VOLGA]`/`[MAX]`
  акцентный).
- exit node: флаг `--mode proxy|raw` выбирает путь выхода в интернет.
  `proxy` (новое значение по умолчанию) обращается наружу обычным
  `net.Dial`, не требует root и правила RST-drop в iptables, и работает на
  любой ОС. `raw` сохраняет прежний путь через самописный raw-сокет (только
  Linux, нужен root), с автоматическим откатом на `proxy`, если raw-сокет
  получить не удалось. Синхронизировано с апстримом.
- экспериментальный транспорт `cupsonline`, использующий трансляцию
  "позиции общего курсора" live-coding-сервиса cups.online как скрытый
  канал. Не подключён в Android-приложении: тестирование показало, что он
  ненадёжно доставляет трафик при включённом шифровании транспорта, так что
  пока считайте его неподдерживаемым (см. таблицу флагов в README).

### Изменено

- ядро exit node (`transport/yandex`, `tunnel`, размер TCP-буферов gVisor)
  приведено к побайтовому соответствию с `main` апстрима
  `p1neappleXpress/OpenFlux`, так что Android-приложение этого форка
  гарантированно работает как с бинарником exit node этого форка, так и с
  немодифицированным апстримовским. Код, который выполняет только клиент и
  никогда не выполняет exit node (авторизация/телеметрия SOCKS5,
  `--url-file`, более аккуратный разбор адреса в `DialTCP`), сохранён как
  собственное дополнение этого форка.

### Исправлено

- счётчик времени соединения сбрасывался в ноль, если приложение открывали
  заново после того, как Android убил свёрнутую Activity (обычное дело
  после долгого отсутствия), хотя сам сервис VPN/Proxy не останавливался.
  Метка "подключено с" теперь хранится в сервисе (который переживает
  пересоздание Activity), а не в Activity.
- нажатие на уже активную вкладку нижней навигации без причины повторяло
  анимацию перекрёстного затухания страницы/иконки; теперь это ничего не
  делает.
- разделитель между строками в списке профилей был с отступом под иконку
  (как в списке настроек); теперь идёт от края до края.
- поле DNS-сервера в VPN отклоняло хостнейм (например, `dns.google`):
  `VpnService.Builder.addDnsServer()` принимает только буквальный IP-адрес и
  падал на всём остальном. Теперь приложение резолвит хостнейм в IP перед
  передачей в builder; локальный DNS-relay и раньше нормально поддерживал
  хостнеймы.
- строки лога с тегом `[CUPS]` транспорта `cupsonline` не окрашивались, как
  остальные теги компонентов на вкладке "Логи".

## 0.5.3 - 2026-09-12

### Исправлено

- краш при подключении, появившийся в 0.5.2: `OpenFluxVpnService` и
  `OpenFluxProxyService` всё ещё отклоняли пустой ключ шифрования через
  `stopSelf()` до вызова `startForeground()`. Поскольку шифрование теперь
  опционально, оставленное пустым поле ключа (как теперь и предлагает сам
  интерфейс) попадало на этот путь при каждой попытке подключения, а
  Android убивает foreground-сервис, не успевший вовремя вызвать
  `startForeground()`, с исключением
  `ForegroundServiceDidNotStartInTimeException` - что роняло всё приложение.
  Оба сервиса теперь вызывают `startForeground()` сразу в `onStartCommand`,
  до любой валидации, способной остановить сервис раньше времени, а их
  проверка ключа шифрования теперь соответствует опциональному поведению
  (отклоняет только ключ, который задан, но короче 16 символов).
- версия Android-приложения теперь 0.5.3 (версия кода 8).

## 0.5.2 - 2026-09-12

### Изменено

- `main` синхронизирован с апстримом `p1neappleXpress/OpenFlux` до коммита
  `4f1bdb5`: Docker-образ и compose-файл для локального запуска
  клиента/exit node, и, самое важное - собственная переработка апстримом
  шифрования транспорта (изначально предложенная этим форком через PR #38),
  которая делает `--encryption-key-file` **опциональным** вместо
  обязательного и применяет его единообразно ко всем транспортам (`yandex`,
  `vyandex`, `oneme`), а не только к `yandex`.
- вслед за этим собственная позиция форка про обязательное шифрование для
  транспорта `yandex` снята: поле ключа шифрования в Android-приложении
  теперь опционально (и подписано/задокументировано как таковое), а
  `mobile.Start`/`mobile.StartProxy` не оборачивают транспорт в
  `EncryptedTransport`, если ключ оставлен пустым - как и в CLI. Пустой
  ключ позволяет приложению работать с обычной, немодифицированной exit
  node апстрима без шифрования транспорта; заданный ключ (16+ символов,
  одинаковый на обеих сторонах) включает AES-256-GCM, как и раньше.
- транспорт `vyandex` теперь подключён к `--transport` в CLI, поскольку
  прежняя причина его исключения (отсутствие собственной обёртки
  шифрования) больше не действует - шифрование теперь единый опциональный
  слой поверх любого транспорта.
- версия Android-приложения теперь 0.5.2 (версия кода 7).

## 0.5.1 - 2026-09-12

### Изменено

- `main` снова приведена к wire-совместимости с текущими бинарниками exit
  node и клиента апстрима `p1neappleXpress/OpenFlux`. Полное сравнение,
  которое к этому привело - в [docs/ru/UPSTREAM_DIFF.md](UPSTREAM_DIFF.md).

Прежний `EncryptedTransport` добавлял 1-байтовую метку типа фрейма перед
каждым пакетом, чтобы мультиплексировать ping и DNS-relay трафик в одном
зашифрованном канале. У транспорта апстрима (включая версию, влитую из
более раннего PR этого же форка) такой метки нет, поэтому клиент одной
стороны не мог работать с exit node другой - лишний байт портил IP-заголовок
у вообще любых данных, а не только у новых функций. Это расхождение возникло
ещё при первом добавлении поддержки ping, а не только на этой неделе с
DNS-relay.

Чтобы это исправить, `main` избавляется от всего, что зависело от
фреймового протокола:

- **граф пинга и отображение страны exit node** (главный экран) - зависели
  от `framePingRequest`/`framePingResponse`;
- **опция "резолвить DNS на сервере"** - зависела от новых фреймов
  `frameDNSRequest`/`frameDNSResponse`, добавленных на этой неделе. DNS на
  Android снова резолвится только локально, как и до работы над
  tunnel-relay на этой неделе, и для VPN-, и для Proxy-режима.

Всё остальное, добавленное с версии 0.4.0, не тронуто и полностью
работает с немодифицированным бинарником апстрима, поскольку ничего из
этого не затрагивает протокол между клиентом и exit node: режим Proxy
(SOCKS5), доступ из локальной сети и SOCKS5-авторизация со ссылкой для
шаринга и QR-кодом, вертикальная навигация настроек и раздел "О программе",
бейдж проверки обновлений на GitHub, живая скорость загрузки/выгрузки и
кнопка отключения в уведомлении, честное отслеживание состояния соединения,
ярлыки для настроек исключения из оптимизации батареи и Always-on VPN, более
полный список активных параметров, запрос `POST_NOTIFICATIONS` и починка
дублирования анимации.

Полный прежний набор функций (фреймовый протокол, граф пинга, отображение
страны, серверный DNS-relay) сохранён в ветке `experimental` для тех, кто
запускает обе стороны на собственном бинарнике exit node этого форка.

- версия Android-приложения теперь 0.5.1 (версия кода 6).

## 0.5.0 - 2026-09-12

### Добавлено

- второй режим подключения для Android: **Прокси (SOCKS5)**, наряду с
  существующим системным VPN-режимом. Использует тот же зашифрованный
  транспорт-документ и тот же пользовательский TCP/IP-стек (gVisor), что
  уже использовал SOCKS5-клиент десктопного CLI, подключённый через
  `gomobile` - изменений протокола или exit node сам по себе этот режим не
  потребовал. В отличие от VPN-режима, не требует запроса разрешения VPN и
  работает как обычный foreground-сервис.
- **DNS-резолвинг через exit node**: и VPN-, и Proxy-режим могут
  ретранслировать DNS-запросы через зашифрованный туннель на exit node,
  которая обращается к настроенному апстриму по обычному UDP из своей сети
  - запрос никогда не касается локальной сети клиента. Новые симметричные
  фреймы `frameDNSRequest`/`frameDNSResponse` в уже существующем
  зашифрованном канале. Настройка для каждого подключения позволяет вместо
  этого выбрать серверный или локальный резолвинг (полезно с exit node,
  которая ещё не обновлена, или когда локальный резолвинг просто быстрее).
- поле DNS-сервера теперь принимает не только IP, но и хостнейм (например,
  `dns.google`, а не только `1.1.1.1`) для обоих режимов резолвинга.
- **доступ из локальной сети и авторизация для Proxy-режима**: опциональный
  переключатель выставляет SOCKS5-listener на `0.0.0.0` вместо только
  loopback, чтобы им мог пользоваться другой девайс в той же Wi-Fi/локальной
  сети, плюс опциональная SOCKS5-авторизация по логину/паролю (RFC 1929,
  проверка учётных данных за постоянное время) с генератором учётных данных
  в один тап. Для сопряжения другого устройства показываются ссылка
  `socks://` и QR-код.
- SOCKS5-сервер теперь отвечает корректной ошибкой на уровне протокола (RFC
  1928 address-not-supported / command-not-supported) вместо молчаливого
  закрытия соединения на IPv6-адресе или не-CONNECT команде, так что клиент
  быстро получает отказ вместо зависания. Полная доставка IPv6/UDP-ASSOCIATE
  пока не реализована - путь exit node в интернет через raw-сокет сейчас
  только IPv4/TCP.
- навигация настроек переделана в вертикальный список в стиле системных
  настроек телефона (иконка + подпись, тап открывает раздел, назад - стрелка
  сверху слева или системная кнопка/жест "назад") вместо горизонтальной
  полосы вкладок, с новым разделом **"О программе"**, ссылающимся на
  репозиторий апстрима и этот форк.
- бейдж версии приложения (раньше статичная плашка "BETA") теперь
  показывает установленную версию и при запуске проверяет GitHub на наличие
  более новой - зелёный ("актуальная версия") или жёлтый ("доступно
  обновление").
- закреплённое уведомление о соединении теперь показывает живую скорость
  загрузки/выгрузки (обновляется раз в секунду) с кнопкой **"Отключить"**,
  для обоих режимов.
- статус соединения теперь честно отслеживает транспорт после начального
  рукопожатия: если зашифрованный транспорт обрывается и незаметно
  переподключается посреди сессии, интерфейс возвращается к "Подключение..."
  вместо того, чтобы продолжать показывать устаревшее "Подключено", и снова
  меняется обратно после восстановления.
- ярлыки для двух системных настроек надёжности: запрос на исключение из
  оптимизации батареи (foreground-сервисы гораздо лучше переживают
  батарейные менеджеры производителей, если разрешение выдано), и ссылка на
  экран настроек Android Always-on VPN / "Блокировать соединения без VPN"
  для VPN-режима.
- карточка активных параметров на главном экране теперь перечисляет все
  значимые настройки для текущего режима (режим, DNS-сервер и место
  резолвинга, MTU или локальный порт, фильтр приложений, статус LAN/
  авторизации), а не только две из них.
- на Android 13+ теперь запрашивается runtime-разрешение
  `POST_NOTIFICATIONS`; без него приложение работало нормально, но молча не
  показывало уведомление вообще.
- анимированные кнопки интерфейса больше не накладывают/дублируют анимацию
  масштаба при быстрых или повторных тапах (общий помощник `bounce()`
  отменяет и заменяет любую текущую анимацию на этом же view вместо
  наложения новой поверх).

### Изменено

- версия Android-приложения теперь 0.5.0 (версия кода 5).
- клавиатура больше не меняет размер всего окна (сжимая нижнюю навигацию и
  кнопку "Сохранить" наверх, в зону видимости); теперь она сдвигает
  содержимое, так что они остаются на месте и просто перекрываются, пока
  поле в фокусе.
- подсказка фильтра VPN по приложениям теперь уточняет, что он применяется
  только в VPN-режиме, поскольку в Proxy-режиме нет системного захвата
  трафика, который можно было бы фильтровать.

## 0.4.0 - 2026-09-12

### Добавлено

- Настройки Android теперь организованы по вкладкам (Транспорт / Сеть /
  Приложения / Вид) вместо одной длинной страницы с прокруткой.
- маршрутизация VPN по приложениям: режим белого списка ("только эти
  приложения используют туннель") или чёрного списка ("все приложения,
  кроме этих"), с выбором из установленных приложений прямо в интерфейсе.
  Реализовано через `VpnService.Builder.addAllowedApplication`/
  `addDisallowedApplication`.
- страна exit node теперь отображается рядом с пингом, как только приходит
  - используя уже существующие зашифрованные ping/pong-фреймы (без нового
  сообщения протокола); exit node определяет её один раз при старте через
  `ip-api.com` и публикует через `EncryptedTransport.SetCountry`.
- анимации по всему интерфейсу Android: перекрёстное затухание при переходах

  GC на exit node для маленьких VPS-инстансов.

  настроек;

- проверки CI для Go и debug-сборок Android.

  root, а не из аргументов командной строки;

### Удалено

- незавершённый прототип под iOS и сгенерированные артефакты IDE/сборки.
